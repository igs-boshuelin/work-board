# 接單看板

編導提需求、我排序估時、TG 自動同步預計完成時間。

零依賴 —— 只用 Node 內建模組，**不需要 `npm install`**，也不會產生 `node_modules`。

---

## 0. 全新安裝（五步）

已經在跑的機器不用看這段 —— 這是給**換一台電腦／另一份 clone** 用的導覽，
每一步只寫「做什麼」，細節都在後面各節。

1. **裝 Node**（我這台是 v18）。零依賴，⛔ 不要跑 `npm install`。
2. **生 `config.json`** —— 把 `config.example.json` 複製一份改名，至少改掉 `adminPassword`，
   `members` 填第一批人。⚠️ `members` / `defaultOwner` **只有第一次啟動會讀**，
   之後名冊住在 `data.json`，再改 `config.json` 不會有任何作用（見 §2）。
   不用 TG 就把 `telegram.enabled` 留 `false`，第 3 步可以整個跳過。
3. **（要 TG 才做）接 bot** —— BotFather 給的 token 先自己貼進 `config.json`，
   把 bot 拉進群組並在群裡送 `/start@你的bot名稱`，然後 `node setup-tg.js` 選聊天室，
   它會把 `chatId` 與 `enabled: true` 寫回去。→ §3
4. **啟動** —— 雙擊 `啟動看板.bat`。防火牆跳出來勾**私人網路**。
   console 印出來的「內網」那個網址就是要給同事的。→ §1
5. **開通每個人** —— 管理者登入 → 人員頁 → 每張卡片按 **發起始碼** → 把碼給本人，
   他自己在管理模式選名字、填碼、設密碼。→ §5

⚠️ `auth.json`、`data.json`、`backup/` **不用手動生**，第一次啟動程式自己會建。
⛔ 反過來說這三個也不要手改、不要進版控 —— 服務跑著的時候程式會整份覆蓋回去（見 §8）。

⛔ **你其實是在「還原」而不是「全新裝」的話，不要走上面這五步。**
舊的工單、名冊、密碼都在加密備份裡，照第 2 步重新生一份 `config.json` 等於從零開始。
還原的流程在 §8.7（以及 work-board-data 那個 repo 的 README）。

⭐ 全新裝完之後，**順手把加密異地備份也接上** —— 那是獨立的一支，跟上面五步無關。→ §8.7

## 1. 啟動

⚠️ **第一次跑之前**：`config.json` 沒有的話 `server.js` 會直接結束。
把 `config.example.json` 複製成 `config.json`，至少改掉 `adminPassword`，
不用 TG 就把 `telegram.enabled` 留 `false`。（`config.json` 帶密碼與 token，**不進版控**。）

雙擊 `啟動看板.bat`（或在這個資料夾執行 `node server.js`）。

啟動後 console 會印出兩個網址：

```
本機   http://localhost:8420
內網   http://192.168.151.70:8420   ← 這個給同事
```

內網那個 IP 是你電腦的區網位址，把它貼給編導就能連。
**你的電腦關機 / 睡眠時大家就連不到**，TG 推播也會跟著停。

### 防火牆

第一次跑的時候 Windows 可能跳「是否允許 Node.js 通過防火牆」→ 勾**私人網路**、允許。
如果沒跳但同事連不進來，用系統管理員身分跑一次：

```bash
netsh advfirewall firewall add rule name="work-board 8420" dir=in action=allow protocol=TCP localport=8420
```

## 2. 設定 `config.json`

```json
{
  "port": 8420,
  "adminPassword": "CHANGE-ME",
  "telegram": { "enabled": false, "botToken": "", "chatId": "" },
  "notifyDebounceMs": 90000,
  "dueSoonMin": 30,
  "projects": [],
  "members": [
    { "id": "boshue", "name": "柏學" },
    { "id": "dirA", "name": "編導甲", "role": "director" }
  ],
  "defaultOwner": "boshue",
  "meetings": [ { "title": "程式會議", "weekday": 2, "start": "16:00", "end": "17:00" } ]
}
```

| 欄位 | 說明 |
| --- | --- |
| `adminPassword` | **一定要改掉**。這是你進管理模式（排序、估時、設完成日）的密碼。 |
| `notifyDebounceMs` | 排程異動後等多久才推 TG，預設 90 秒。你連續改一串時只會收到一則彙整訊息，不會洗版。 |
| `projects` | 提需求表單「專案」欄的預設候選清單。留空也沒關係，用過的專案名會自動變成候選。 |
| `members` | **只是第一次啟動的種子。** 名冊實際住在 `data.json`，之後改這裡不會有任何作用。`role` 不填＝ `dev`（接單的人）；填 `"director"` 就是**編導**，只提需求、不接單（見 §4）。 |
| `defaultOwner` | 同上，只有第一次啟動會拿。沒指定負責人的需求預設算誰的。 |
| `dueSoonMin` | 「快到預計完成時間」提前幾分鐘提醒，預設 30（1–480 的整數，填錯會**開不起來**並印出原因）。見 §3〈不看訂閱範圍的兩種通知〉。 |
| `meetings` | 每週固定會議，那段時間排不進單，也不會被算進推估完成日。見下。 |

### 固定會議 `meetings`

```json
"meetings": [
  { "title": "程式會議", "weekday": 2, "start": "16:00", "end": "17:00" },
  { "title": "美術同步", "weekday": 4, "start": "10:00", "end": "11:00", "members": [ "boshue" ] }
]
```

- `weekday`：`0` 是週日、`1` 週一 …… `2` 就是**週二**。
- `members` 不填＝全員都要開；填了就只有名單上的人被佔用，其他人照常排單。
- 右側排程會畫成一格 🗓，跨過會議的單會被切成兩段、剩下的往後推；
  卡片上的 `≈` 推估完成日也跟著算進去。
- 格式寫錯（`weekday` 不在 0–6、時間不是 `HH:MM`、`end` 比 `start` 早）**會直接擋下啟動**
  並告訴你錯在哪一筆 —— 悶著跑下去只會得到一份不知道哪裡不對的排程。
- **兩場撞在一起是可以的**（16:00–17:00 與 16:30–17:30）：重疊的那半小時只會被扣一次。
  ⚠️ v5.4 之前會被扣兩次，結果是「實際工時」變負數、那一整段時間表畫不出來。
- 這是唯一沒有網頁入口的設定，改完要重啟。

> **人員要加減，在網頁上做，不要改這個檔**（人員頁的 **＋ 新增人員**，見 §4）。
> 名冊在 v3 已經搬進程式自己管的 `data.json` —— 兩個檔各存一份遲早會對不起來，
> 而且程式去寫 `config.json` 的話，你手改到一半就會被下一次寫入蓋掉。
> 第一次啟動時 `config.json` 裡至少要有一個人，不然會擋下來告訴你怎麼補。

改完 `config.json` 要**重啟服務**才生效。

## 3. 開 Telegram bot

只有**第 1 步**要你自己做（BotFather 只認你的 TG 帳號），其餘交給設定助手。

**步驟 1｜拿 token（你做）**
TG 裡找 **@BotFather** → 送 `/newbot` → 照著取名 → 它會給你一組 token（像 `8123456789:AAH...`）。
把 token 貼進 `config.json` 的 `telegram.botToken`。

**步驟 2｜把 bot 加進編導的群組**，然後在群裡送一則：

```
/start@你的bot名稱
```

> ⚠ 一定要用**斜線指令**。TG bot 預設開著 privacy mode，看不到群裡的普通訊息，
> 只發「哈囉」它是收不到的，設定助手就會找不到那個群。

**步驟 3｜跑設定助手**

```bash
node setup-tg.js
```

它會驗證 token、列出 bot 看得到的所有聊天室讓你用數字選、自動把 `chatId` 與
`enabled: true` 寫回 `config.json`，最後發一則測試訊息。選好之後**重啟服務**。

沒設定或 `enabled: false` 時**不會壞**，訊息只會印在 server console，可以先這樣試跑。

### 手動改 `config.json` 的注意事項

**不要用記事本存檔** —— 它的 UTF-8 會加 BOM，`JSON.parse` 會炸在 position 0，
錯誤訊息完全看不出原因。用 VS Code 存成「UTF-8」（不是 UTF-8 with BOM）。

程式本身會自動剝掉 BOM，所以真的存錯了也還是跑得起來；但其他 JSON 語法錯誤
（少逗號、多逗號、引號沒成對）會在啟動時就擋下來並告訴你原因。

### 推播時機

只有這五種異動會推：**估時**、**預計完成日**、**狀態**、**轉派**、**預估完成**。
改標題、改備註、有人留言 → 不推（避免洗版）。

**外加一種：有新單進來。** 那不是「異動」，所以訊息長得不一樣（🆕 開頭，寫誰提的、
落到誰身上），但走同一個彙整佇列 —— 一次貼五張只會收到一則。詳見下一節。

**「預估完成」是排序造成的。** 你把一張單往前拖，後面每一張真的都會變晚 ——
那是提需求的人最該知道、但以前完全看不到的事。現在後端會重算（見 §6），
被推遲的那幾張會各自通知它們的提出者。

同一個欄位在彙整期間被改好幾次，只留**最初 → 最後**；改過去又改回來（例如拖錯馬上拖回來）
等於什麼都沒發生，**不會發通知**。不收斂的話，90 秒內拖兩次順序訊息會變成一串中間狀態的流水帳。

**逐筆異動預設只走個人訂閱，不進群組**（見下一節）。
群組只會收到你手動按 📣 推的那一則。想把群組彙整開回來：`config.json` 的
`telegram.notifyGroup` 設成 `true`。

訊息長這樣：

```
📌 工作排程更新（2 項異動）

• [迦羅戰神500] 停輪音效比畫面早半拍
  估時 未估 → 3h；預計完成 未定 → 09/18
• [賭神500] 內購按鈕在斷線重演後不見
  狀態 待評估 → 已排程

──────────
🔵 進行中（1）
  • [迦羅戰神500] 停輪音效比畫面早半拍 — 預計 09/18（3h）
🟡 已排程（2）
  ...
```

右上角的 **📣 推播** 按鈕可以無視 debounce，立刻把目前整份排程丟到群裡（例如週會前）。

### ⭐ 不看訂閱範圍的兩種通知（v5.5）

上面那些都要「訂閱範圍對得上」才會收到。有兩種訊息例外，**不管你訂了什麼都會私訊你**：

| 什麼時候 | 訊息開頭 | 收件人 |
| --- | --- | --- |
| **有新的項目落到你名下**（別人開單直接指給你、或管理者把單轉派給你） | `👤 有項目指派給你` | 那張單的負責人本人 |
| **快到那張單的預計完成時刻**（預設提前 30 分鐘） | `⏰ 快到預計完成時間了` | 同上 |

> ⚠️ **「不管有沒有訂閱」的真正極限：這兩種也只走 Telegram 私訊，所以沒綁 TG 的人收不到。**
> bot 沒辦法主動私訊一個從沒跟它講過話的人（見下一節），**沒綁＝沒有送達位址**，
> 不是程式挑人。要收到就得照下一節綁一次 —— 綁完之後訂閱範圍可以全部不勾，
> 這兩種照樣會來。

**⛔ 自己動的不會回頭吵自己。** 自己開單給自己、自己把無主單撿到自己名下 → 不發。
判斷的是「這次是誰按的」，⛔ 不是「範圍對不對得上」—— 你自己訂的範圍就算涵蓋這張單，
一般異動照樣照收。

**⛔ 也不是「我名下的任何異動都算指派」。** 只認**新單**與**換負責人**兩件事。
別人把一張大單轉給你，會把你名下其他單的預估完成日往後推 ——
那些位移**不會**被夾帶進這則「指派給你」裡（否則佇列一動就洗版一次）。

#### 「快到預計完成時間」是怎麼算的

- 看的是**排程推算出來的完成時刻**（分鐘級，右側欄那條佇列一路加總出來的），
  ⛔ **不是卡片上的「預計完成日」** —— 那個只有日期，推不出「前半小時」。
- 只看 `🔵 進行中` 與 `🟡 已排程` 而且**估過時**的單（沒估時就沒有完成時刻）。
- **只在正常工時內響**（`workHours.normal`，⛔ 不扣會議 —— 開會中也是上班，訊息照收）。
  下班後才輪到的那張，會等到隔天上班、真的快做完時才響。
- **每分鐘掃一次**，所以 `dueSoonMin` 是「最多提前這麼多分鐘」。
- 響過會在那張單記一個 `dueNotified`（寫進 `data.json`），**同一張不會每分鐘再響一次**。
  ⚠️ 推估會漂（別人插件、改估時、拖順序都會讓時刻前後移動），所以去重有**一小時的容忍度**：
  漂動超過一小時會被當成「這已經是另一個時間點了」而重響一次。

> 訊息長這樣：
>
> ```
> ⏰ 快到預計完成時間了
>
> • [迦羅戰神500] 停輪音效比畫面早半拍
>   預計 15:30 做完，還有 28 分鐘
>   （你排的完成日 09/18）
> ```

### 訂閱通知（🔔）

每個人自己訂閱，只收到跟自己有關的異動 —— 這樣群組才不會被洗版。

**怎麼訂**：**先登入**（v4 起訂閱綁的是帳號，不是打的名字）→ 網頁右上角 **🔔 訂閱通知**
→ 視窗上的「訂閱者」直接顯示你是誰，不用填 → 產生一組 6 碼
→ 在 Telegram **私訊** bot 送 `/bind 那組碼`（或直接點「在 Telegram 開啟」）。

> 沒登入時那個視窗只會顯示「訂閱要先登入」＋ 一顆去登入。
> 綁帳號是為了「改顯示名稱不會把訂閱弄丟」，也讓一個人只會有一份訂閱。

> ⚠️ **bot 沒辦法主動私訊一個從沒跟它講過話的人**，這是 Telegram 的硬限制。
> 所以一定要由本人去找 bot，不是你把他加進去就好。
> 也**不要在群組裡送** `/bind` —— 那樣存到的會是群組 id，之後「私訊」會發到整群去
> （程式只認私訊，群組裡送會被忽略）。

**訂閱範圍**（`scopes`，存在 `auth.json`）—— 訂閱視窗裡直接勾，可以複選：

| 寫法 | 網頁上的名字 | 意思 |
| --- | --- | --- |
| `requester:dirA` | 我提的需求 | 那個**帳號**提的需求（預設就勾這個；冒號後面是人員 id，不是顯示名稱） |
| `owner:` | **還不確定找誰的** | **沒指定負責人的單，一進收件匣就通知** |
| `owner:boshue` | 某個人的單 | 某個人負責的全部 |
| `project:迦羅戰神500` | 某個專案 | 某個專案的全部 |
| `all` | 全部需求 | 全部 |

勾了「全部需求」其他項就會變灰 —— 反正都被涵蓋了。

> **`owner:`（冒號後面留空）就是「還不確定找誰」的收件匣。**
> 這條是給「沒人認領的單不能爛在那裡」用的：誰訂了它，只要有人提了一張沒指定負責人的單，
> 他馬上會收到一則 🆕，訊息裡會明講 **⚠️ 還沒指定負責人**。
> ⚠️ 會這樣是因為**新單進來本身就會發通知**（對所有範圍對得上的訂閱者，不限無主單）。
> 以前只有「單子被改」才通知，那對無主收件匣沒用 —— 沒人動它就永遠不會響。

**改範圍不用重綁。** 訂過了再打開一次，送出鍵會自己變成「更新追蹤範圍」——
綁定拿到的是 TG chat id，那個沒變。也還是可以直接改 `auth.json` 的 `scopes`
陣列，但那樣**要先關服務**再改（見 §9）。

> ⚠️ `requester:` 與 `owner:xxx` 裡填的人員 id 會被後端驗，**打錯直接擋下來**。
> 不驗的話一個錯字會變成「訂閱看起來有生效、但永遠不會響」。
> 唯一可以留空的是 `owner:`（無主收件匣）—— `requester:` 留空一樣擋。

勾了「也 @ 我一下」的人，在你手動按 📣 推播時，如果排程裡有他相關的項目，
訊息尾巴會 @ 到他。用的是 `tg://user?id=`，所以**沒設公開 username 的人也 tag 得到**。

> ⚠️ 服務跑起來之後就會一直在輪詢 TG（long polling，不是狂打 API）。
> 這時候**不要再跑 `node setup-tg.js`** —— 兩邊同時要 `getUpdates`，TG 會回 409。
> 要重跑設定助手就先把服務關掉。

## 4. 畫面：外層人員頁 → 內層看板

打開網址先看到的是**人員頁**，一個人一張卡：

```
🧑‍💻 柏學          📥 還不確定找誰       🙋 我提的需求
 1 進行中           1 等人接              3 未完成
 1 待評估
 0 逾期
 目前排到 09/18
```

點進去才是那個人的看板。**進到誰的頁面，就是跟誰提需求** —— 表單送出時
`owner` 帶的就是當下這一頁的人。

三種入口：

| 卡片 | 網址 | 內容 |
| --- | --- | --- |
| 某個人 | `#m=<人員 id>` | 那個人的看板 ＋ 右側他的排程 |
| 📥 還不確定找誰 | `#m=_open` | `owner` 是空字串的無主單 |
| 🙋 我提的需求 | `#m=_mine` | 跨所有人，抓 `requesterId` ＝**你登入的帳號**（沒登入就是空的） |

**「還不確定找誰」是故意留的退路** —— 不知道該找誰的需求有地方放，
不會被硬塞給某個人。無主的單**任何登入的人都能接走**（下拉選「接給我」），
不用等總管理者分派；但**接走之後就有主了**，再要換人只有總管理者能轉。

「我提的需求」是唯讀的：它跨了不同人，在那裡排序等於替別人決定順序，
所以那一頁沒有拖曳、沒有估時欄、也沒有「我要提需求」按鈕。

**卡片上的 `≈ 09/18`** 是推估完成日（見 §6），只有還沒手填「預計完成」的單才顯示 ——
兩個日期同時出現會不知道該信哪個。

### 搜尋與篩選（篩選列）

看板上方那一列由左到右是：**搜尋**、**專案**、**提出者**、**顯示已完成**、**⬇ CSV**。

搜尋比對這些欄位：**單號、標題、明細、備註、專案、提出者、留言內容**。
邊打邊篩（監聽 `input` 不是 `change`），不用按 Enter，大小寫不分。
單號也比是刻意的 —— TG 通知與系統留言裡寫的都是 `t0012` 這種格式，貼進來要找得到。

⭐ **有打關鍵字時會刻意忽略「顯示已完成」**（`app.js` 的 `visibleTasks()`）——
否則搜一個做完的東西會一片空白，人只會以為那張單不存在。
⛔ 不要把這個條件「修正」成一致，它是故意不一致的。

⚠️ **搜尋只看眼前這個看板**（跟專案／提出者兩個篩選同一套範圍，都是 `scopeTasks()`）。
別人板上有符合的時候，看板頂端會出現一行「🔎 其他看板還有 N 筆」——
沒有那行提示的話，在 A 的板上搜不到就會以為全公司都沒有這張單，
那種「找不到」比沒有搜尋更糟。實作是 `elsewhereHint()`。

### 編導也是名冊上的帳號（v4）

v4 之前編導不用登入、提需求時自己打名字。現在**提需求要先登入**，
所以每個編導都要在名冊裡有一個帳號，角色標成 **編導**：

- 人員牆下面有獨立的一區「編導」，卡片是扁的、不能點進去 ——
  他們不接單，沒有自己的看板。**負責人下拉選單裡也不會出現他們。**
- 加編導：人員牆編導那區的 **＋ 新增編導**（或在編輯視窗把角色改成編導）。
  開通方式跟其他人一樣，發一組起始碼給他（見 §5）。
- 已經有單掛在名下的人**不能**改成編導，會擋下來 —— 改了那些單會變成沒人接。

> 為什麼要這樣：以前「提出者」是一段自由文字，同一個人打「小明」「小明(美術)」
> 會變成兩個人，訂閱也追不到；改個顯示名稱就整串斷掉。
> 綁帳號之後，**提出者、訂閱、「我提的需求」三件事是同一個身分**。
>
> 舊單沒有帳號可對的（例如已離職的人）不會被動掉：`requester` 那段文字原樣留著，
> 只是沒有 `requesterId`，所以不會出現在任何人的「我提的需求」裡。

### 加人、改人（只有總管理者看得到）

登入後人員牆最後面會多一張虛線的 **＋ 新增人員**，每張人卡右上角也會多一個 **✎**。

| | |
| --- | --- |
| 顯示名稱 | 畫面上顯示的，隨時能改（訂閱與提出者綁的是代號，所以改名不會弄丟任何東西） |
| 代號 | 英數與 `-` `_`，最多 24 字。會出現在網址（`#m=<代號>`）裡 |
| 角色 | **接單的人**（預設）或**編導**。編導不會出現在負責人選單與人員牆上半部 |
| 全權管理者 | 勾了就能排所有人的單、發起始碼、推播 |

**代號建立後不能改**，編輯時是唯讀的 —— 那是 `tasks[].owner` 跟 `days[日期][人]` 的鍵，
改了等於把他名下的單全部變成孤兒，而且不會有任何錯誤訊息。

加完人**立刻生效、不用重啟**，接著幫他發一組起始碼（見 §5）就能用了。

**移除**在編輯視窗左下角。名下還有單的話會擋下來並告訴你有幾筆 ——
先把那些單轉派給別人或刪掉再移除。移除會一併刪掉他的密碼、還沒用掉的起始碼、
排程快照，而且**至少要留一個人**。

**不能移除自己**：自己的編輯視窗沒有移除鈕，後端也會擋（409）。
移除等於連帳號一起刪，刪自己就再也登不進來 —— 2026-09-29 有人為了調順序把自己刪掉，才加的。
真的要刪自己，請另一位管理者來做。

**調順序用拖曳**：全權管理者在人員牆上直接拖人卡（只有接單的人的卡能拖），放開就存。
順序存在 `data.json` 的 `members` 陣列，負責人選單等地方也跟著這個順序。
⛔ 以前唯一的調法是「刪掉再加回來」—— 現在不需要了，而且會弄丟密碼跟排程快照。
另一個視窗剛好新增／移除了人的話，拖曳會被擋下來，請重新整理再拖一次。

> 改了某人的「全權」勾勾，他當下開著的視窗會被登出 ——
> 權限是登入那一刻記下來的，不踢掉就會跟名冊對不起來。

### 登入時選人

右上角 **🔑 管理模式** 的第一格是「你是誰」，選自己再輸密碼。
最後一個選項「總管理者」走的是 `config.adminPassword`。
只有一個人員時那一格會自動藏起來。

還沒設過密碼的人選自己時，會多一格「起始碼」（見 §5）。

> 人員只有一個人的時候，人員頁看起來會有點多餘 —— 那是刻意的，
> 資料形狀先照多人存好，之後加人不用回頭補「這張單當初是誰的」。

### ❓ 說明（看板內建的團隊說明頁，v5.6）

右上角 **❓ 說明** 是給團隊看的操作說明 —— 整份寫死在 `public/index.html` 的
`#help-modal` 裡（純靜態，沒有 API、沒有資料）。分兩塊：

- **🆕 最近更新** —— 開著的公告區，講「這幾天變了什麼」
- 下面十個可折疊的段落 —— 第一次來 / 三個入口 / 提需求 / 三個日期 / 一張單怎麼走 /
  被插件 / 排程表怎麼算 / 補帳跳窗 / TG 通知 / 誰能做什麼

⚠️ **改完公告要把 `public/app.js` 的 `HELP_VERSION` 換掉**，否則按鈕上那顆紅點
不會重新亮起來，公告等於沒人看到。它存在每個人自己瀏覽器的 `wb_help_seen`
（**不進伺服器** —— 這是「這台瀏覽器看過了」，不是「這個人看過了」），
打開視窗的那一刻就算看過，⛔ 不是等他捲到底或按關閉。

`#help-modal` 也要算進 `catchUpAllowed()` 與 `busy()` 那兩份「有視窗開著嗎」的清單
（`app.js`）—— 少了它，說明開著時補帳跳窗會疊上來、20 秒輪詢也會在人在讀的時候重繪看板。

⭐ **說明頁裡的時間數字不要寫死**（2026-09-21）—— 工時／加班那三段與「快到預計完成時間」
提前幾分鐘，都是 `config.json` 說了算。`index.html` 只放空殼 `#wh-hint`／`#help-wh`／`#due-soon`，
由 `app.js` 的 `renderWorkHoursText()` 與開機那段從 `meta` 現填。
⛔ 改工時不會有人記得回來改文案 —— 脫鉤的說明比沒有說明更糟。
⚠️ `#due-soon` 在**舊後端**（`meta.dueSoonMin` 是 undefined）時整句括號不畫，不會印出 `undefined`。

> 這份說明跟這個 `README.md` 的分工：**說明頁只寫「用的人要知道的」**，
> 啟動方式、`config.json`、資料格式、踩坑紀錄一律留在 README。
> 兩邊都寫一次的東西（例如估時的四種寫法）以 README 為準，改了記得回頭同步說明頁。

## 5. 誰能做什麼

| | 沒登入 | 編導（登入） | 登入的人員（自己的單） | 總管理者（別人的單） |
| --- | :---: | :---: | :---: | :---: |
| 看清單、看進度、看預計完成時間 | ✅ | ✅ | ✅ | ✅ |
| **新增需求** | ❌ | ✅ | ✅ | ❌＊ |
| **留言討論** | ❌ | ✅ | ✅ | ✅ |
| **排序（拖曳）** | ❌ | ❌ | ✅ | ❌ |
| **估時 / 設預計完成日 / 改狀態** | ❌ | ❌ | ✅ | ❌ |
| **改「🙏 希望完成」** | ❌ | ✅＊＊ | ✅＊＊ | ❌ |
| **存每日排程快照** | ❌ | ❌ | ✅ | ❌ |
| 轉派給別人 | ❌ | ❌ | ❌ | ✅ |
| 改標題 / 專案 / 說明 / 備註 | ❌ | ❌ | ✅ | ✅ |
| 刪除 | ❌ | ❌ | ✅ | ✅ |
| 加減人員、發起始碼、手動推播 | ❌ | ❌ | ❌ | ✅ |

> ＊＊ 「希望完成」只有**提出這張單的那個人**改得動 —— 負責人與總管理者都不行
> （2026-09-18 起）。那是編導對自己需求的宣告，不是排程；別人代改的話，
> 之後對帳分不出「他要得急」跟「我幫他改了」。詳見 §7〈「希望完成」…〉。

> ＊ **「總管理者」那組密碼（`config.adminPassword`）沒有綁到人**，所以它提不了需求
> ——「提出者」要是一個真的帳號。要提需求就用自己的人員帳號登入。
> 畫面上會直接寫這句，不會讓你按了才失敗。

> **提需求與留言都要登入（v4 起）。**
> 以前這兩處都是自己打名字，等於任何人都能用別人的名義提單、留言，
> 而那條留言看起來跟真的一模一樣。現在署名一律從登入的 session 來，
> 前端就算送了 `requester` / `who` 欄位也會被後端忽略。

> **排程與評估只有本人能動，總管理者也不行。**
> 別人的順序排不排得下、一張單要做多久，只有他自己知道；
> 管理者要保證的是「單子有人負責、內容正確」，不是替他決定怎麼做。
> 管理者對別人的單剩下三件事：**轉派、改文字、刪除**。
>
> 例外是**無主的單**（負責人「還沒指定」）—— 它還沒有「本人」，
> 所以任何登入的人都能先估時、先排，接走時只能接給自己。

編輯方式：點開任一張單 → **✏️ 編輯這張單**（只有文字欄位）；
估時、完成日、狀態在卡片上那一列直接改，看不到那一列就是你不能改。

### 想讓「提出者」篩選少一個名字

那個篩選選單是**從現有需求算出來的**，沒有獨立清單可以刪。
v4 之後新提的單，提出者一律是帳號，所以會留在那裡的通常是**舊單**
（提出者那段文字對不上任何帳號，例如離職的人）。要讓它消失就是讓沒有任何一張單掛著它：
改掉那幾張單的負責人與內容、或直接刪掉。專案的篩選也是同樣的邏輯。

管理模式：右上角 **🔑 管理模式** → 輸入 `adminPassword`。
token 存在瀏覽器 localStorage，**服務重啟後會失效**，重新輸入一次即可。

> 這是內網信任環境的設計：有帳號、有密碼，但沒有 HTTPS、沒有防重放。
> 保護的是「不會有人誤動我的排序、不會有人用我的名義提單」，不是防惡意使用者。

### 人員與密碼

名冊裡每個人可以有自己的密碼，登入後**只能改自己 `owner` 的項目**：

| | 沒登入 | 人員登入 | 總管理者 |
| --- | :---: | :---: | :---: |
| 看全部 | ✅ | ✅ | ✅ |
| 提需求、留言 | ❌ | ✅ | ❌（沒綁到人） |
| 估時 / 完成日 / 狀態 / 排序 | ❌ | 只有自己的 | ❌（只有本人能動，見上） |
| 刪除 | ❌ | 只有自己的 | 全部人 |
| **轉派給別人** | ❌ | ❌ | ✅ |
| 手動推播 | ❌ | ❌ | ✅ |

總管理者有兩種：`config.adminPassword`（不綁人，是名冊或密碼弄壞時的後路），
以及名冊裡勾了**全權管理者**的人（用自己的密碼登入就是全權）。

### 新人員怎麼開通（起始碼）

在人員頁按 **＋ 新增人員** 加進來之後，**他還不能自己設密碼** —— 要你先發一組起始碼給他。
沒有這道手續的話，任何連得進內網的人都能搶先幫別人把密碼定下來；如果那個人是
全權管理者，那等於全權被別人拿走。

1. 你用管理者身分登入 → 回到**人員頁**（外層）→ 那個人的卡片上會有 **發起始碼**
2. 跳出一組 6 碼，把它給本人（口頭 / 私訊都行）
3. 他在 **🔑 管理模式** 選自己的名字 → 畫面會多一格「起始碼」→ 填碼 ＋ 自己想用的密碼 → 完成

| | |
| --- | --- |
| 有效期 | 7 天 |
| 用幾次 | **一次**，設完就失效 |
| 打錯 | 10 次就自動作廢，要你重發 |
| 存在哪 | `auth.json` 的 `setup`，**只存 scrypt 雜湊**，不是明文 |

> ⛔ **那組碼只會顯示那一次。** 伺服器只留雜湊，沒有「再看一次」的地方 ——
> 忘了就按**重發**（舊的同時作廢）。發錯人就按**收回**。

**忘記密碼**走的是另一條路：總管理者在管理模式下直接幫他重設，不需要起始碼也不需要舊密碼。
（已經有密碼的人按發起始碼會被擋下來 —— 兩條路都通的話，起始碼就變成繞過舊密碼的後門。）

有人設定 / 重設密碼，或起始碼被發出、收回、試錯作廢時，console 都會印一行 `[auth] ...`。

> 卡死了還有最後一條路：關掉服務、刪掉 `auth.json`、重開。
> 所有人的密碼與訂閱會一起沒掉（待辦資料不受影響），大家重設一次。

排序是**只重排你送出去的那幾筆**：每個人在自己頁面拖曳，只會用到自己那幾筆原本的位置，
其他人的順序一個字都不會被動到。

## 6. 排程（右側欄）

把待辦依序塞進今天剩下的上班時間，算出每一項大概幾點做。

**時段**

| | 時間 | 長度 |
| --- | --- | --- |
| 上午 | 9:00–12:30 | 3.5h |
| 下午 | 13:30–18:00 | 4.5h |
| 加班 | 18:30–22:00 | 3.5h（⛔ 不排單，見下）|

⭐ **加班段不排單**（2026-09-21 起）—— 表上永遠只排到 **18:00**，18:30–22:00 那段
只是說明用的，⛔ 不會自動塞任何單進去。要不要留下來趕是人自己決定的，
看板不替人假設他會做到 22:00。

> 這一版之前是「正常工時塞不下就自動往加班塞」，於是右邊那張表當你**一定加班**、
> 卡片上的 `≈` 卻當你**永遠不加班**（見 §6〈推估完成日〉，後端只吃 `workHours.normal`）
> —— 兩套假設打架。現在兩邊是同一套。

⭐ **不排單 ≠ 不記帳**：你**真的做到 18:00 之後**（那個時間才按完成／被插件）的那幾張，
照樣畫在加班段上。⛔ 不可以連已發生的一起擋掉 —— 超過 8 小時的那幾張會從表上默默消失
（`overflow` 會把已發生的濾掉），那就是 v5 之前「做完的事看不到了」那個災情。
實作是 `planDay()` 裡那道 `if ( b.ot && !ready[ qi ].past ) break;`。

⚠️ 連帶：**18:00 之後打開看板**，沒設過起排時間的話預設會跳回隔天早上 9:00（表整份重畫）。
以前是 22:00 之後才這樣。要看當下的樣子就自己把起排時間調回去。

**固定會議**（`config.json` 的 `meetings`，見 §2）會在表上畫成一格 🗓，
那段時間排不進任何單。預設有每週二 16:00–17:00 的程式會議。
跨過會議的單會被切成前後兩段（第二段標「續」），會議吃掉的時間**真的會往後推**，
不是「當作有在做」。

**排法**

0. **今天已經做完的（`✅`）先佔住它實際花掉的時間**，灰色顯示在最前面
1. 接著排 `🔵 進行中`，再排 `🟡 已排程` —— 各自照你在左邊拖出來的順序
2. `📥 待評估` 不排（還沒估時、還沒排序，不該佔今天的格子）
3. 沒填估時的不排，另外列在下面提醒你
4. **18:00 前塞不下的就塞不下了**（⛔ 不往加班塞）→ 紅框「⛔ 做不完（N 項）」，
   `⚠️ 今日到期` 標出真的會開天窗的
   （只做了一半的那筆會寫「已排一部分，還差 N 分」，不會整筆重算）

一項做不完會跨時段切開，第二段標「續」。點任何一列都能開那張單。

**起排時間是每個人各一份的**（v5.2 起），存在伺服器上（`data.json` 的 `dayStarts`，
`日期 → 人員 → { min, auto, by, at }`）。同事請假、遲到，他那天本來就不是從上班時間
開始算；而且換一台電腦、換一個人來看，看到的都是同一份。

誰能調：**本人，或管理者**（幫遲到／請假的同事調）。其他同事看得到、調不動，
那一格會是灰的（後端 `/api/day-start` 擋的是同一條，不是只有前端擋）。

⚠️ `/api/day-start` 與 `/api/day-plan` 這兩個寫入（v5.4 起）**一定要帶 `owner`**，
沒帶就回 `400`。原本沒帶會退回 `defaultOwner`，所以「還不確定找誰」那一頁存出來的
排程快照會掛到他名下、汙染他當天的紀錄。`min` 也只收 `0–1439` 的整數或純數字字串，
⛔ 不再吃 `null` / `""` / `true`（以前會被硬轉成 `0` / `0` / `1`，起排變午夜）。

⚠️ 這比「排程與評估只有本人能動、管理者也不行」鬆一格，是刻意的：起排只決定
**這張表從幾點開始畫**，不會動到任何人的單、估時或順序。

**預設值**分兩種情況（v5.1 起）：

- **今天還沒發生過任何事** → 「現在往上取整到 5 分鐘」。下午才開就從下午開始。
- **今天已經有做完的單、或有被插件留下的區間** → 直接從**上班時間**開始（`blocks` 第一段）。

⚠ 第二條是補一個真的踩到的坑：起排**之前**做完的東西不會被畫出來（見下一節），
所以起排一旦定得比「今天第一件事」還晚，那些事會整批從時間表上消失、整個早上顯示
「未排」。2026-09-17 服務掛了一早上，11:20 才第一次打開看板，11:18 做完的單只差
兩分鐘就被丟掉。⛔ 所以不可以只看時鐘，要看今天有沒有已經發生過的事。

⚠ 起排時間**一旦定下就不會再跟著時鐘跑**。不定住的話，晚上八點再打開一次，
整個下午的排程會因為「現在是 20:00」而憑空消失。⭐ 「定下」＝伺服器上那天那個人
已經有一筆了；之後不管誰重整幾次、從哪台電腦開，都照那一筆走。
隔天是另一張表，自動回到預設。

存起來的那筆會記 `auto`：「這個值是自動算的，還是有人自己調的」。

- **有人自己調的**（`auto:false`，本人或管理者改過那一格）⇒ 當天絕對不會被蓋掉。
  他可能就是要只看下午。⭐ 這條**前後端都擋**（v5.4 起）：後端收到「`auto:true` 要蓋掉
  一筆 `auto:false`」時回 `409`、資料不動。原本只有前端擋，兩個分頁搶著寫、
  或直接打 API 就會蓋掉人自己調的值。
- **自動算的**（`auto:true`）⇒ 只有在「**已經發生過的事正被起排擋在外面**」時
  才會往前拉，而且只往前、不往後。

⚠️ 「被擋在外面」這個條件不能省。少了它，你每按一次完成都會把起排往回搬：
12:00 打開、12:20 按下完成，起排會自己跳回 9:00，剛做完那張單就被記成做了
3 小時（估時才 1 小時），整個上午都算在它頭上。

另外兩條同樣不能省的條件：

- **只有看自己的看板時才會自動定案／自動救。** 管理者路過看別人一眼，不該把人家
  的起排定死在「他被看到的那一刻」—— 那個人可能還沒到公司。別人的看板只是照
  算出來的畫給你看，等他自己開的時候才定案。要幫他調得用手動改那一格（`auto:false`）。
- **拉了也畫不出來的事不算數。** 上班時間**之前**做完的（或被會議整段吃掉的）事，
  時間表本來就不畫；把起排拉到 9:00 也還是不會出現，只會讓整個早上被還沒做的單
  填滿，看起來像「我九點就在做這些」。所以這種事件不列入「今天發生過的事」。

### 已經發生過的事會佔住時間（`✅` 與 `⏸` 那幾段）

起排凍結的前提是「佇列不會縮水」。但你每按一次完成，那張單就從佇列裡消失了 ——
後面每一張會立刻往前遞補，補進**已經過去的時段**。17:37 按完成，表上卻說下一張
「14:35 開始」，那是假的。

所以今天**已經發生過的事**會留在時間表上，灰色、排在最前面，佔住它真的花掉的那段。
有兩種：

| | 什麼時候留下 | 那一列寫什麼 |
| --- | --- | --- |
| `✅` | 今天按下**完成**（`doneAt`） | `實際 3h（估 3h）` |
| `⏸` | 今天做到一半**被插件**、離開「進行中」（`spans`，見 §7） | `已做 2h` |

被插件那種還會**同時出現在後面**：前面一段灰色的是今天已經做掉的，
後面一段是它剩下的估時。⛔ 這不是重複，不要去重 —— 少了前面那段，
它今天花掉的時間就會從表上消失，後面整批往前塌，
那個時段看起來就變成**另一張進行中的單**（v5 之前就是這個症狀）。

- 時長用「**上一件結束 → 這一件結束**」的實際間隔推（第一件從起排算起），
  不是估時、也不是 `spans[].min` —— 估時是事前猜的，`min` 是人回報的工作量
  （中間跑去做別的它不知道），只有時間戳是真的發生過的。
- 中午休息、下班到加班之間的空檔、以及**固定會議**都會扣掉，
  不然做一整個下午會被算成連午休跟開會都在做。
- 起排**之前**就做完的不畫 —— 那段時間本來就不在這張表的範圍裡。
- 連續兩張之間你如果去開臨時會、去吃飯，那段時間會被算進後面那張（固定會議除外，
  那個已經扣掉了）。這張表看的是
  「時間花到哪去了」，不是工時計。

一個附帶好處：**收工時回頭看，就是今天實際的時間流水帳**，而且會自動存進當天快照。

### 回看以前的排程

標題旁邊的下拉選單可以切到**過去某一天**，看那天收工時的排程長什麼樣。

- 你在管理模式下每動一次（改估時、拖順序、改狀態），4 秒後會自動存一份當天的快照，**同一天只留最新的一份** —— 所以回看到的是那天最後的樣子，不是早上剛開時的樣子。
- 編導那邊只是看，**不會寫壞你的快照**（後端擋掉非管理者的存檔）。
- 切到歷史時「起排」欄位會變灰 —— 那天已經過去了，改它沒有意義。
- 歷史畫面上的 `⚠️ 今日到期` / `🔴 已逾期` 是**用那天當基準**算的，不是用今天，
  所以回看舊排程不會整片變紅。

> 這張表只看估時，**不看預計完成日**。它回答的是「照這個順序做，今天做得到哪」，
> 不是「今天該做哪些」。要改順序就去左邊拖。

### 推估完成日（卡片上的 `≈`）

右側那張表只算「今天」，**推估完成日算的是跨天**：照目前的順序與估時，一天一天往後排，
算出每一張大概哪天做得完。這是後端算的，所以拖完順序、改完估時馬上就會更新。

- **只用正常工時推**（9:00–12:30、13:30–18:00），週末跳過。
  把加班當成常態去算，得到的日期是騙人的。
  ⭐ 2026-09-21 起右側那張「今天」的表也是同一套（以前它會排加班）。
- `📥 待評估`、`⏸️ 擱置`、沒估時的都不進佇列，所以它們沒有 `≈`。
- **每個人各排各的** —— 大家是平行在做，甲的排序不會把乙的往後推。
- 跟「預計完成」是兩回事：`due` 是你手動給的**承諾**，`≈` 是目前排法推出來的**後果**。
  兩個對不起來，就是該調順序或該改承諾了。
- 服務重啟時會先算一次但**不通知** —— 跨了一天本來就會位移，那不是誰改了什麼。

## 7. 狀態

`📥 待評估` → `🟡 已排程` → `🔵 進行中` → `✅ 已完成`（另有 `⏸️ 擱置`）

編導送出的需求一律進**待評估**。排序、估時、給日期都是你的動作。

### 做到一半被插件（`🔵 進行中` → 別的狀態）

長專案做到一半被插件，回頭再撿起來時，卡片上那個估時**已經不是還要做多久了**。
所以從「進行中」改成「已排程 / 擱置」時會跳一個框問你**剩下還要幾小時**：

```
「大廳改版」要從進行中改成已排程。

目前估時 6h，這一輪已經做掉大約 5h24m（照上班時段推的，午休跟固定會議已經扣掉）。

還要多久？可以填 1.5、1h30m、90m 或 1:30。不對就改掉再按確定。   [ 36m ]
```

- 預設值是**推的、不是量的**：從進入「進行中」那一刻算到現在，扣掉午休、下班、
  週末與固定會議。⚠️ **國定假日它不知道**，那種日子會多算一天 ——
  所以它只是個預設值，**不對就直接改掉**。
- 按**取消**＝整個動作不做，狀態不會變（畫面上的下拉會彈回原本的）。
- 存下去之後卡片會寫 **`⏱ 原估 6h・已做 5h24m・剩 36m`**，這三個數字**永遠**加得起來
  ——「已做」是後端從估時的差算的，不是前端送什麼就存什麼。
  ⚠️ 這是這個功能**唯一的硬保證**，後端算在分鐘上，⛔ 顯示時不要先四捨五入成
  `0.1h` 再印（那樣會加不起來，v5 之前就是這樣）。
- ⭐ **v5.4 起這條保證沒有例外了**（原本的 Bug B，2026-09-17 修）。以前有兩條路會讓它
  對不起來，現在兩條都由後端補平：卡片上**直接改估時**（只寫 `estimate`、不動那筆帳），
  以及被插件時填的「還要多久」**比原本剩的更多**（原估 1h、還要 2h ⇒ 1 ≠ 0＋2）。
  作法是把「原估」補成 `已做 ＋ 剩`。
  ⚠️ 代價：**`原估` 的意思是「現在認為總共要多久」，⛔ 不是「第一次填的那個數字」**
  —— 每次重估剩餘時數都會把它往上推。原估 1h 的單改成「還要 2h」之後，
  卡片寫的是 `原估 2h・已做 0m・剩 2h`。
  ⛔ 沒有選「改估時就把 `estimate0` / `spentMin` 清掉」那條路：`spentMin` 是真實工時，
  清掉的話時間表上的灰色區間還在、卡片卻說沒做過。
- ⭐ **v5.4 之前留下來的爛帳，開機時會補一次**（只補一次，之後開機不會再吵）。
  補的時候黑窗會講清楚是哪幾筆、原估從多少變成多少，例如：
  `⚠ 有 1 筆單的「原估 ＝ 已做 ＋ 剩」對不起來（v5.4 之前手改估時留下的），`
  `   已經把原估補成「已做 ＋ 剩」：t0017（原估 2h → 5h）`
  ⚠️ 這是**正常的一次性補帳，不是錯誤**。⛔ 但它會真的改寫 `data.json`
  （重開當下就寫，不用等有人去動單），所以在意舊數字的話先備份 `data.json` 再重開。
- 再被插一次會**累加**，原估不會被中間那個數字蓋掉。
- 同時會在 `spans` 留下一筆「這一輪從幾點做到幾點」，右側時間表靠它畫出
  那段灰色的 `⏸`（見 §6）。⚠️ 沒有 `startedAt` 的單（v5 之前就卡在進行中的）
  不會留這筆 —— 表上少一段，比畫一段編出來的區間好。
- 改成 `✅ 已完成` 不會問也不會動這筆帳 —— 做完了，剩餘時數沒有意義。
  也**不會**留 `spans`，已完成走 `doneAt` 那條路，兩邊都記會在時間表上畫兩次。

#### 時間怎麼填（v5）

估時與「還要多久」這兩格都收四種寫法，內部一律存小時數：

| 你打 | 意思 |
| --- | --- |
| `1.5` / `.5` | 小時 |
| `1h30m` / `1h30` / `1.5h` | 時＋分 |
| `90m` / `90分` | 分鐘 |
| `1:30` / `:45` | 時:分 |

顯示一律印成 `1h20m` 這種寫法。
⛔ 不要改回印小數 ——「剩 1.33h」是使用者明確說看不懂的那個東西。
打錯字會回 400 並把可用寫法列給你，**不會**默默存成 0。

### 「希望完成」是編導填的，不是你的承諾

提需求的表單上有**希望完成**：選日期，時間可留白（留白＝那天之內都可以）。
時刻**任何分鐘都可以**（`10:29` 也收）—— v5 之前卡在半小時一格，
picker 只給整點半點、打字打進去又會被表單擋掉。
卡片上顯示成 `🙏 希望 09/25 14:00`，**過了就變紅**。

跟另外兩個日期分清楚：

| | 誰給的 | 意思 |
| --- | --- | --- |
| 🙏 希望 | 編導 | 他想要的時間，你沒答應任何事 |
| 📅 預計完成（`due`） | 你 | 你給出去的**承諾** |
| ≈ 推估（`projectedDue`） | 程式 | 照目前排法推出來的**後果**（見 §6） |

> v4 之前這格是自由文字，會收到「這週內」「下次送審前」這種排不進去的東西。
> 現在只收日期＋時刻。**舊單裡看不懂的那些文字不會被丟掉**，
> 轉檔時搬進「說明」欄並標明是原本的希望時程 —— 那是編導唯一講過「什麼時候要」的地方。

#### 改它的人只有提出者，而且每一次都留紀錄（2026-09-18）

提出單之後想改時間，去那張單的詳細視窗按 **🙏 改我希望完成的時間**。
走的是專屬端點 `PATCH /api/tasks/:id/wish`（⛔ 不是編輯表單那支 `PATCH /api/tasks/:id`）。

**誰能改**

- ✅ 只有 `requesterId` 對得上的**本人**。
- ❌ 負責人、總管理者都不行 —— 這是 2026-09-18 **收緊**的，之前他們改得到而且不留痕跡。
- ❌ v4 之前沒有 `requesterId` 的舊單（或離職的人提的）**沒有「本人」⇒ 誰都改不了**。
  ⚠️ 這是刻意的：寫入權限只認 id，⛔ 不退回比名字（名字會重複、會改，猜錯沒人會發現）。
  真的要改，先關掉服務、手動把那張單的 `requesterId` 補上（見 §8 的 `data.json`）。

**硬性限制**

- ⛔ 不能改到**今天之前**（今天可以）。填了只會讓卡片立刻變紅，等於用一個假的逾期催人。
  前端用 `<input min>` 擋一層，後端再擋一層。
- ⛔ **已完成的單**不能改。
- 日期／時刻格式看不懂 → 400，⛔ **不會**默默存成空的（那跟「我要清掉」分不出來）。
- 送一樣的值（表單沒動就按了儲存）→ 200 但**不留紀錄、不推 TG**。

**留下的三個痕跡**（⭐ 三個都要：只留紀錄不通知的話，被改的人不會發現）

| 留在哪 | 長什麼樣 | 給誰看 |
| --- | --- | --- |
| `task.wishLog[]` | `{ at, by, from, to }` | 卡片與詳細視窗上的 `·改過 N 次` |
| `task.comments[]` | `⚙ 系統紀錄：小柔 把希望完成從「09/23 14:00」改成「09/20 09:30」（這張單第 1 次改）` | 討論區，跟人的留言排在一起 |
| TG 彙整 | `🙏 希望完成 09/23 14:00 → 09/20 09:30` | 訂了這張單的人 |

⚠️ TG 那則走**既有的 90 秒彙整**（跟估時／狀態同一則）⇒ 同一張單在 90 秒內改好幾次，
訊息只會留「最初 → 最後」。**每一步**要看討論區的系統紀錄，那裡一次都不會少。

⚠️ 系統紀錄那幾條帶 `sys: true`（前端靠它畫成灰底）。
⛔ 不要讓前端去猜 `who` 的前綴 —— 那個字串改了不會有人發現。

⚠️ `/api/meta` 的 `wishApi: true` 是**能力旗標**：舊後端還沒重開時它是 `undefined`，
前端就不畫那塊表單（否則會是一顆按了回 404 的按鈕）。⛔ 不要改成前端寫死版本號。

### 隔天早上會問你「昨天做了多少」（v5.6）

打開自己的看板時，如果有下面任一種情況，畫面會自動跳出一個視窗請你把帳補平：

**觸發條件（聯集，缺一不可各自滿足）**

| 規則 | 條件 |
| --- | --- |
| A 快照命中 | 最近一個有你的排程快照的日期，裡面有排進去（`segs`）、但狀態停在 `🟡 已排程`／`🔵 進行中` 的單 |
| B 跨日進行中 | 一張單的 `startedAt` 早於今天，狀態仍是 `🔵 進行中` |

**基準日**是「最近一個早於今天、而且你有快照的日期」，**不一定是昨天** ——
週末、請假、那天沒打開看板都會讓昨天沒有快照，這時基準日會往前找。

**只問你自己，不問管理者**。管理者路過看別人的看板不會觸發。

**「全部都沒做」也算問過了**。按下去之後那幾張當天不會再問，要改估時請用卡片上既有的那條路。

**一張單一天只能補一次**。同一天重送會被當成「已經補過了」直接放行，數字不會被加兩次。
要再修就改卡片上的估時。

**補帳不會在右側時間表上長出灰色區間**。數字會進「已做」欄位，但那天的時間表已經凍結了
（同一天的快照只留最新一份，補帳刻意不寫 `spans`，詳見 §6）。

一張單同時被排進去又溢出（排了 3h、但那天只剩 1h 能塞）**算「排了」**，一樣會問。

## 8. 資料

- `data.json` —— 全部資料在這一個檔，可以直接看、直接備份。
  - `members` 是人員名冊、`defaultOwner` 是沒指定負責人時算誰的。
    **v3 之後這裡才是正本**，`config.json` 的同名欄位只是第一次啟動的種子（見 §2）。
    要加減人請用網頁（§4），手改這裡跑著的服務不會知道，而且會被下一次寫入蓋掉。
  - `members` 每筆的 `role`：`dev`（接單）或 `director`（編導，只提需求）。
  - `tasks` 是待辦本體，每筆帶 `owner`（誰做的）與 `requesterId`（誰提的，**人員 id**）。
    `owner` 是**空字串**＝「還不確定找誰」，不是壞資料。
    - `requester` 是**顯示名稱的快照**，只給對不上帳號的舊單看；有 `requesterId` 時以帳號為準。
      `requesterId` 是**空字串**＝這張舊單對不上任何帳號（例如離職的人），不是壞資料。
    - `wishDate` / `wishTime` 是編導希望的完成時間（`YYYY-MM-DD` / `HH:MM`，都可留空）。
      v4 之前的自由文字欄 `wish` 已經不存在了。
    - `wishLog` 是**改過幾次希望完成**的紀錄（`{ at, by, from, to }`，見 §7）。
      開單時填的那個不算改 ⇒ 沒動過的單是空陣列。⚠️ 跟 `spans` / `comments` 一樣，
      開機時會在**記憶體裡**補成 `[]`（⛔ 不寫回檔案），所以從備份貼一筆回來不用自己補。
    - `estimate0` / `spentMin` 是被插件時留下的帳：**目前認為總共要**幾小時、
      已經做掉幾分鐘（見 §7）。⚠️ `estimate0` 不是「第一次填的估時」——
      v5.4 起只要重估剩餘時數就會被補成 `spentMin/60 + estimate`，
      好讓卡片上那三個數字永遠加得起來。
      `spentMin` 是**後端算的**，前端送進來會被忽略。沒被插過的單 `estimate0` 是 `null`。
    - `startedAt` 只在狀態是 `🔵 進行中` 時有值，用來推「這一輪做了多久」，離開就清掉。
    - `spans` 是被插件時留下的區間 `[ { from, to, min } ]`（v5 起），右側時間表靠它
      畫出灰色的 `⏸`（見 §6）。`from` / `to` 是時間戳、`min` 是人確認過的「做掉多少」。
      ⚠️ 只有**離開「進行中」但沒完成**才會加一筆；按完成走 `doneAt`，不寫這裡。
      沒被插過的單是**空陣列**，不是 `undefined`（轉檔會補）。
    - `dueNotified` 是「快到預計完成時間」提醒響過的那個時刻（`YYYY-MM-DDTHH:MM`，見 §3）。
      沒響過的單**沒有這個欄位**，不是壞資料。把它刪掉＝那張單會再響一次。
    - `catchUpAsked` 是「補帳守門（§7）已經問過的日期」（`YYYY-MM-DD`，v5.6 起）。
      沒問過的單**沒有這個欄位**，不是壞資料。把它刪掉＝那張單今天會再問一次。
  - `projectedDue` 是程式算出來的推估完成日（見 §6），**改它沒有意義**，下一次重算就蓋掉。
  - `days` 是每天的排程快照，形狀是 `"2026-09-16": { "boshue": {...} }` —— 日期底下再分人。
  - 快照只是畫面用的紀錄，**刪掉不會影響待辦**，覺得太多了可以整段清掉。
  - `v` 是資料格式版本。**不要手動改它** —— 改小了會再跑一次轉檔，改大了該跑的轉檔會被跳過。
- `auth.json` —— 各人員的密碼雜湊（scrypt，不是明文）＋ 還沒用掉的起始碼（`setup`，也是雜湊）
  ＋ 訂閱者的 TG 資料。程式自己建、自己寫。
  - ⛔ **不要跟人分享、不要丟進備份群組**（裡面有大家的 TG chat id）。
  - `subscribers` 的鍵是**人員 id**（v4 起；以前是名字的雜湊）。
    轉檔時對不上帳號的舊訂閱者會留在原本的鍵底下**繼續收通知**，不會被刪掉 ——
    只是他沒辦法在網頁上改自己的範圍，要嘛幫他建帳號重綁、要嘛手改這個檔。
  - `v` 是這個檔的格式版本，跟 `data.json` 的分開算。
  - 想改訂閱範圍可以手動編 `scopes`，但**要先把服務關掉**再改，改完再開 ——
    服務跑著的時候改，你的修改會被下一次寫入蓋掉，而且不會有任何錯誤訊息。
  - 刪掉它 = 所有人的密碼與訂閱都沒了，各自重設一次即可（待辦資料不受影響）。
- `backup/data-YYYY-MM-DD.json` —— 啟動時與每 6 小時各存一份，改壞了可以蓋回去。
- `backup/data-before-vN-YYYY-MM-DD.json` —— 資料格式升級前自動留的原樣備份。
  升級完發現不對勁，把這個檔蓋回 `data.json` 就回到升級前。

搬到別台機器：整個資料夾複製過去就好。

## 8.5 已知限制（裁決過不處理）

- **兩個分頁同時改同一張單沒有鎖**（2026-09-21 裁決不處理）—— 後送出的那筆整份覆蓋，
  `wishLog` 會留兩筆。四個人的看板，撞車機率低，而且**不會壞資料**，所以不加樂觀鎖。
  ⚠️ 症狀是「我改的怎麼不見了」—— 重新整理會看到別人那版。
- **沒有 `requesterId` 的舊單，希望完成誰都改不了**（2026-09-21 裁決不處理）——
  只剩 `t0012`／`t0013` 兩張，而且都沒設過希望完成。要解只能關服務手動補欄位。
- **CSV 不擋試算表公式**（2026-09-21 裁決不處理）—— 備註裡寫 `=1+1`，用 Excel 開會被當公式算掉。
  ⚠️ **加引號擋不住這個**（引號只防欄位被切錯位），要擋得在值前面塞一個單引號、
  等於改掉人家打的字。內部看板、填的人跟看的人是同一批，不值得。
- **`GET /api/tasks` 與 `GET /api/export.csv` 不需要登入** —— 內網上任何人都讀得到全部工單
  （寫入的端點都有擋）。這是為了讓別的表單／腳本抓得到資料。
  ⛔ 哪天要把服務對外開，這**兩支要一起加權限**，只擋一支等於沒擋。

## 8.6 匯出 CSV ／ 給別的表單接

**網頁上**：看板篩選列右邊的 **⬇ CSV**。滑鼠移上去會寫清楚這次拿到的是什麼 ——
在某個人的看板上＝那個人的全部工單，在「還不確定找誰」＝無主的那些，
在「我提的需求」＝**全部人**（後端那支只認 `owner`，切不出「誰提的」這個子集，
寧可多給也不要給一份內容對不上標題的檔案）。

⚠️ **匯出的是整個看板，不受上面的搜尋與篩選影響。** 這點在按鈕的 tooltip 寫死了 ——
以為拿到的是眼前篩完的結果、實際是全部，是會出事的那種誤會。

**程式接**：

```
GET /api/export.csv               # 全部
GET /api/export.csv?owner=boshue  # 只出這個人的
GET /api/export.csv?owner=        # 只出還沒指定負責人的
GET /api/tasks                    # 同一份資料的 JSON（原始欄位，沒有轉成中文）
```

欄位順序：`單號, 標題, 專案, 提出者, 負責人, 狀態, 估時(h), 已花(h), 希望完成, 指定完成,
推估完成, 建立, 完成, 備註, 明細, 留言數`（定義在 `server.js` 的 `CSV_COLUMNS`）。
⚠️ 有人拿去接表單之後，要加欄位請**往後加**，不要插在中間。

實作上的三個細節，⛔ 都不要「順手清掉」：

- **開頭那三個怪位元組是 BOM**（`\uFEFF`）。少了它 Excel 開中文會變亂碼。
- **換行一律 CRLF**，包含欄位內嵌的換行（明細常常是多行的）。混著 LF 的話
  Excel 有些版本會把整格擠成一行看不出斷行。
- **每一格都加引號**，不逐種判斷。值裡的 `"` 會變成 `""`（RFC 4180）。

**時間欄位是本機時間**（`YYYY-MM-DD HH:MM`），不是 `data.json` 裡的 UTC ——
差 8 小時的「完成時間」剛好會跨日，跟排程表對不起來。

## 8.7 異地備份（GitHub，config 加密）

`backup/` 跟 `data.json` 在同一顆硬碟，硬碟掛了兩份一起走。
所以另外有一支把資料推到第二個 private repo：
[work-board-data](https://github.com/igs-boshuelin/work-board-data)。

| | |
|---|---|
| 備份哪些 | `config.json`、`auth.json`、`data.json` 三個（都是被 gitignore 的那幾個） |
| 怎麼包 | **只有 `config.json` 加密**（botToken、adminPassword）：gzip → **AES-256-GCM** → `vault.enc.json`。<br>`auth.json`、`data.json` **明碼原樣放**，在 GitHub 上看得到每次改了什麼 |
| 金鑰 | `vault.key`（64 個 16 進位字元）。⛔ **不進版控** |
| 誰在跑 | Windows 工作排程器，呼叫 `備份到雲端.bat` |
| 紀錄 | `backup-vault.log`（每跑一次一行；⚠️ 是 UTF-8，PowerShell 的 `Get-Content` 要加 `-Encoding UTF8` 才不會是亂碼） |

**為什麼三個都備**：只備 `data.json` 的話，硬碟掛掉還是要重設所有人的密碼
（`auth.json`）、重貼 botToken（`config.json`）。那是「還原得回來」跟「還原得回來但要花一個下午」的差別。

**為什麼只加密 config**（2026-09-23 裁定）：工單與名冊是內部資料、沒有機密，repo 本身也是 private；
真正外流會出事的只有 botToken（能冒用 bot）與 adminPassword（看板全權）。
⚠️ `auth.json` 裡是密碼的 scrypt 雜湊（不是明碼），接受以明碼存放。
⛔ **要把哪個檔從加密改成明碼前先想清楚**：明碼推上去就永遠在 git 歷史裡，事後改回加密也收不回來。
（2026-09-23 之前的舊備份三個檔都在密文裡，`restore` 照樣讀得出來。）

### ⚠️⚠️ 金鑰不能只放在這台電腦上

`vault.key` 遺失 ⇒ **雲端上的 `config.json` 永遠解不開**（工單與密碼還在，但要重貼 botToken、重設 adminPassword）。
所以那 64 個字元一定要另外抄一份到**密碼管理器**（或任何不在這顆硬碟上的地方）。
換一把新金鑰也一樣 —— 舊的備份會全部解不開，要換請先把舊金鑰連同當下的
`vault.enc.json` 另存一份。

### 指令

```bash
node backup-vault.js init       # 只有第一次：產金鑰，並印出來叫你去抄
node backup-vault.js push       # 備份＋commit＋push（排程器跑的就是這支）
node backup-vault.js verify     # 把雲端那份抓下來解開，確認真的還原得回來
node backup-vault.js restore    # 解到 restored/ 底下
```

⭐ **每次 push 都會「加密完立刻解回來對一次」才寫出去** —— 少了這一步，
「備份有在跑」跟「備份解得開」是兩件事，而你會在需要它的那天才發現是後者。

⭐ **內容跟上一次一樣就整個跳過，不產生 commit。** 比對的是**明文的雜湊**（連同格式版本 `LAYOUT`），
⛔ 不能比密文 —— 每次 IV 都不一樣，密文必定不同，比密文等於什麼都沒改也天天 commit。
⚠️ 所以有 commit 時 `vault.enc.json` 一定也會跟著變，就算 config 沒改 —— 看 diff 時忽略它就好。

### 還原

```bash
node backup-vault.js restore
```

三個檔會寫到 `restored/`（config 解密、其餘兩個從 repo 複製），**不會**直接蓋回去。⛔ 這是刻意的：
看板服務跑著的時候蓋掉 `data.json`，記憶體裡那份會在下一次 `saveData()`
把你還原的東西整份蓋回來，**而且不會有任何錯誤訊息**。
要用的話：關掉服務 → 手動把 `restored/` 裡的檔複製過去 → 重開。

（在一台全新的電腦上還原的完整步驟寫在 work-board-data 的 README，
那份跟備份放在一起，硬碟掛掉時你手上就只剩它。）

### 設定工作排程器

在 PowerShell 跑這一行（只要做一次）：

```
schtasks /Create /TN "工作看板加密備份" /TR "D:\H5\_ai-tools\work-board\備份到雲端.bat" /SC HOURLY /MO 3 /ST 09:00 /F
```

每 3 小時跑一次（09、12、15、18、21、00、03、06）。半夜那幾次因為資料沒變會直接跳過，
不會產生 commit，成本只有 log 裡多一行。

⚠️ **只有在你登入著的時候會跑**（schtasks 的預設）。這是刻意的 ——
推上 GitHub 要用到 Windows 認證管理員裡的憑證，改成「不論是否登入都執行」反而會拿不到而失敗。
反正看板服務本來就跑在這台登入的機器上。

**跑了但失敗會發 TG**：`push` 出錯時（金鑰讀不到、git push 被拒、網路斷…）發一則到
`config.json` 的 `telegram.chatId`，用的是看板同一個 bot。
看板服務有沒有在跑都不影響（備份直接讀 `config.json`）；`telegram.enabled` 是 `false` 就不發。

⚠️ **但「排程根本沒跑」是沒有人會通知你的**（關機、排程被刪、沒登入）—— 沒跑就沒有程式能發通知。
偶爾打開
[work-board-data 的 MANIFEST.txt](https://github.com/igs-boshuelin/work-board-data/blob/main/MANIFEST.txt)
看一眼「備份時間」——⛔ 不要看 commit 的間隔，資料沒變本來就不會 commit。
